# Security and privacy

The public site has no attack surface beyond two POST routes. The CMS is protected in layers: the unlock link, a password, a one-time code, and a server-side session check on every `/admin` load and action. Everything below matches TNL unless marked **TuinZorg**.

- **Server-only secrets.** The database URLs, storage keys, the deploy hook, the Brevo key, the Google key and the unlock key are Worker secrets or build variables. None is imported into client code; use `$env/static/private` and `$env/dynamic/private` only.
- **Three database roles.** `tz_app` (read/write, used by the Worker), `tz_build` (read-only on content tables, used by the prerender; no access to `requests`, `request_files` or the auth tables) and `tz_backup` (read-only on every table, used only by the nightly dump). None is the Neon owner role.
- **Every CMS mutation re-checks the session** in its form action or endpoint, not only in the layout. SvelteKit's built-in origin check stays on against CSRF.
- **Uploads:** type sniffed from the bytes, size capped, object keys are server-generated UUIDs, no SVG.
- **TuinZorg: visitor uploads.** Request photos are accepted only together with a request that passed the honeypot, Turnstile and rate limit; at most five, 10 MB each, 25 MB in total; JPEG, PNG or WebP by their bytes. They are stored under `requests/`, are never public, and are served to the CMS only through signed URLs that expire after 5 minutes.
- **Markdown** in bodies and area intros is rendered at build time and sanitised (no raw HTML, links get `rel="noopener"`).
- **Forms:** Zod validation, length caps, honeypot, Turnstile (invisible "managed" mode), and the rate-limit binding at 5 submissions per IP per 10 minutes. Notification mails contain the text but never raw HTML.
- **TuinZorg: confirmation mail to the visitor.** It goes only to the address in a request that passed every check, has a fixed text (no form content except the first name and the chosen services), and counts against the same rate limit, so the form cannot be used to send mail to strangers.
- **TuinZorg: Google key.** The Places API key is restricted to the Places API (New) and used only by the cron, server side. A daily quota in Google Cloud caps it well under the free monthly credit.
- **Headers** in `_headers`, for every path: `Strict-Transport-Security: max-age=31536000; includeSubDomains` (no `preload` until the real domain is live), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`, `frame-ancestors 'none'`.
- **CSP** through SvelteKit's `kit.csp` in `hash` mode. Directives: `default-src 'self'`; `script-src 'self' https://challenges.cloudflare.com https://static.cloudflareinsights.com`; `frame-src https://challenges.cloudflare.com https://www.google.com`; `img-src 'self' data: blob:`; `style-src 'self' 'unsafe-inline'`; `font-src 'self'`; `connect-src 'self' https://cloudflareinsights.com`; `form-action 'self'`; `base-uri 'self'`. In `/admin`, `img-src` also allows the storage endpoint for the signed request-photo URLs.
- **Privacy (GDPR):** requests hold personal data, including addresses and photos of private gardens. Store only the form fields and the time, with no IP address. The daily cron deletes requests and their photos after 12 months; Aanvragen offers a CSV export first. The privacy page (`/privacy`) says what is collected, why, for how long, and who to contact; the team drafts it and the client approves it. The quote form links to it next to the consent checkbox.
- **No cookies on the public site** except Turnstile's own when it challenges: Cloudflare Web Analytics is cookieless and the map loads only on click, so no cookie banner is needed. Recheck this whenever a third-party embed is added.
- **Backups.** Neon Free keeps only 6 hours of point-in-time restore, so:
  - `.github/workflows/db-backup.yml` (nightly 02:30) runs `pg_dump` with the `tz_backup` role, gzips it and uploads it to the R2 bucket `tz-backups`, with a lifecycle rule that deletes dumps after 30 days. The dump contains requests, so the bucket is private and the R2 token is limited to the two backup buckets.
  - The one free Neon snapshot is taken right before every production migration.
  - Content photos are covered by the weekly mirror (see [Media](04-media.md)). Request photos are not mirrored; losing them in a disaster is acceptable, since the owner already has each request by mail.
  - `HANDOVER.md` describes a restore, rehearsed once on the `dev` branch in phase 6.
